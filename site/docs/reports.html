Reports

A run writes eight files. The report is built from facts the board has checked and from fixed templates; the Reporter's own text is cut by a lint and labelled as model text wherever it appears.

The files#

FileWhat it holds
report.htmlThe report as one file that makes no request to any other site. It shows the structure of the file next to the bytes the findings point at.
report.mdThe same report as Markdown. Text that came from a sample or an agent is escaped, so it cannot become HTML, a link or a code fence.
report.jsonThe same report as data, in a fixed format whose number is recorded in the manifest.
board.jsonEvery finding with its level and status, every refused post with its code, the counts and the ATT&CK techniques.
iocs.csv, iocs.stix.json, iocs.misp.jsonThe indicators: the sample's own hashes and the checked findings that nobody disputes. The evidence level travels with each row. The real values are here; iocs.csv also has a defanged column.
detection.yarYARA rules written from byte-checked strings. It is written only when the file has enough of them.

report.md has these sections, in this order. Rounds is written when the run recorded a plan or a summary for a round.

  1. Assessment
  2. Executive summary
  3. What it is
  4. Capabilities
  5. Recommendations
  6. What we don't know
  7. Sample snapshot
  8. Indicators of compromise
  9. Functions
  10. Cryptography and configuration
  11. Capability findings
  12. Notes on the file
  13. Unconfirmed claims
  14. MITRE ATT&CK
  15. Detection engineering
  16. Disputes
  17. Rounds
  18. About this report
  19. Analysis environment

What the report states as fact#

The sample snapshot is SwarmLabRE's own reading of the file: no agent wrote those values. A finding is stated with its evidence level, offset and cited calls only after it passed the board's checks. The sentences about what a finding means are fixed templates. Network indicators are defanged in the report copies, for example hxxps://updates[.]example[.]test/check.

A finding that is only claimed is not stated as fact. It is left out of report.html and listed as a lead under "Unconfirmed claims" in report.md and report.json.

What is model text#

The Reporter's sections, its suggestions, what it says it could not establish and its reasoning for the verdict are model text. SwarmLabRE removes sentences that break its rules, then labels what is left:

The label under each piece of Reporter text is:

label in the report
Written by the Reporter agent. Model text: swarmlabre removed internal references from it but does not check it.

Next to the Reporter's text the report adds standard actions and standard limits in fixed wording, chosen from what was verified.

The assessment#

The Reporter ends its text with a verdict, a confidence, an optional family and the ids of the findings the verdict rests on. SwarmLabRE keeps only what the board can check:

  • The basis keeps only findings that are verified or disputed. Cited findings that are not are dropped, and the report says so.
  • A verdict of malicious or suspicious needs at least one finding in the basis. Without one it is shown as undetermined.
  • Confidence is capped by the evidence. High needs two findings in the basis, one of them byte-checked, and none of them disputed. One finding gives at most moderate, and none gives low.
  • A benign verdict never goes above moderate confidence, because static analysis does not prove a file is safe.
  • When SwarmLabRE lowers the confidence or changes the verdict, the report says so in fixed words.

The verdict is one of malicious, suspicious, benign (shown as "No malicious behaviour found") or undetermined. It is the model's opinion and changes no count, level or hash.

Which findings reach which file#

A finding's status decides where it appears. The board says how each status comes about.

  • A refuted finding is left out of the body of the report. report.md and report.json name it in the Disputes section with the verdict, and every report counts it.
  • A refused post is kept in board.json with its code. The reports count refused posts and do not list them.
  • The indicator files take verified findings of kind ioc, and config findings whose value is an address, a domain, a URL or another network artifact. A disputed finding is shown in the report and left out of these files.
  • A YARA rule uses only verified, byte-checked strings of kind ioc, crypto or config. SwarmLabRE reads the bytes at each offset again and matches every rule against its own copy of the sample, with its own matcher, before the rule is written. No rule is written when the assessment is benign, when detection_rules is false, or when the sample is not kept.

TLP marking#

Every run carries a Traffic Light Protocol marking. It is on the cover of report.html, on the first line of report.md, in a column of iocs.csv and in the metadata of each YARA rule. The default is AMBER. Set it with tlp in the [swarm] section of the configuration, with --tlp on run, or on the launch sheet.

MarkingText in the report
CLEARDisclosure is not limited.
GREENLimited disclosure, restricted to the community.
AMBERLimited disclosure, restricted to the recipient's organization and its clients.
AMBER+STRICTLimited disclosure, restricted to the recipient's organization.
REDNot for disclosure, restricted to the named recipients only.

report_org, report_contact and report_logo in the same section add a "Prepared by" line, a contact line and a logo to the cover.
