swarmlabre alpha 0.1.0

Static malware analysis by a swarm of AI agents, with findings checked against the file.

Up to six AI agents analyse one binary (ELF, PE or APK) at the same time. They share one findings board, and swarmlabre checks every finding against the file's own bytes and against the tool calls the run really made. The report is built from the checked facts; the agents' prose is labelled as model text. A finished run is sealed and replays offline to byte-identical report files.

How it fits together

The agents run in containers with --network none and never hold the model's key; the model reaches them only through a socket swarmlabre owns. Everything the agents or the sample print is untrusted text.

A report is a single file, report.html, that makes no request to any other site. Here is one, from the recorded demo run: a harmless generated program, analysed by a scripted mock model.

What "reproducible" means here

Every run is sealed with a manifest.json (tool version, sample hash, model and sampling, image ids, and the SHA-256 of every input and output file), the board's inputs in order, and every model exchange. swarmlabre replay rebuilds the board and all report files offline from that record and fails if one byte differs. A live run is pinned (temperature and seed are forced on every request) and recorded, but not promised to repeat: six agents share one model.

Nothing signs manifest.json. The hashes catch accidents, and forgeries that forgot the manifest; someone who edits a file and recomputes the hashes gets a replay that agrees. The details, and what the 11 golden cases do not cover, are in docs/determinism.md.

Look first: Python 3.12 only, no Docker, no GPU, no key, no network

The repository carries a recorded run and 11 golden cases. All of this works after a plain git clone:

git clone https://github.com/virqdroid/swarmlabre
cd swarmlabre

# rebuilds every report file offline; exit 0 only if every byte is the recorded one
python3 -m swarmlabre replay demo/sfaef16e6

# the web UI playing that recording
python3 -m swarmlabre serve --replay demo/sfaef16e6 --speed 8

# the whole suite, golden cases included
python3 -m unittest discover -s tests

# replay every golden case twice and compare with the committed outputs
python3 tests/goldenrun.py --check --twice

Docker is needed only to analyse a new file (the agents and Ghidra/jadx run in containers). The tools image compiles Ghidra's decompiler for arm64, so that part runs on arm64 Linux only today.

What this is not

  • Not a sandbox for running malware: the sample is only read, never executed. Do not point it at a file you could not safely open in a disassembler.
  • Not a claim that a verdict is right. A verdict, a family name and a confidence are a model's opinion, capped by what the board could check. A finding marked byte-checked means the bytes are there at that offset; it does not mean the agent's reading of them is correct.
  • Not repeatable for a live model run. Replay of a recording is byte-identical; a second live run on the same file can differ.
  • Not tested on other CPU architectures or with more than one model, and no check in this repository involves real malware: the tests and the demo use generated benign files only. The tools image builds for arm64 only today.

Status

Alpha, 0.1.0. It was built and checked on one machine (Linux arm64, Python 3.12.3). This page and the demo were opened in headless Firefox only, not in other browsers. Please read SECURITY.md, which lists what is defended against and what is not claimed, before you point swarmlabre at a real malware sample. It is a one-person project.
