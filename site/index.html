Agents claim. The bytes confirm.

Up to six AI agents analyse one binary (ELF, PE or APK) and post to one board. SwarmLabRE checks every finding against the file's own bytes and the run's own tool log. The report is built from the checked facts, the agents' prose is labelled as model text, and a finished run replays offline to byte-identical report files.

One run, in five steps

The recorded run of demo2.elf, with a scripted mock as the agents.

  1. The host parses the file

    demo2.elf is an ELF of 552 bytes, SHA-256 4f514261553c…. SwarmLabRE reads and parses it on the host and never runs it.

  2. Two containers, both without a network

    A tools container opens the file and writes what the agents read. The agents run in a second container.

  3. The agents post findings

    Up to six roles work at once. In this run, seven posts reached the board.

  4. The board checks every post

    Five were byte-checked, one stayed unconfirmed and one was rejected as a duplicate.

  5. The report is written and the run sealed

    The report is built from the checked findings. manifest.json holds the SHA-256 of every input and output.

Where each part runs

The agents run in containers with --network none and never hold the model's key; the model reaches them only through a socket SwarmLabRE owns. Everything the agents or the sample print is untrusted text.

Replay rebuilds every file, or exits 1

Every run is sealed with:

  • manifest.json: the tool version, the sample hash, the model and sampling, the image ids, and the SHA-256 of every input and output file
  • the board's inputs, in order
  • every model exchange

swarmlabre replay rebuilds the board and every report file offline and exits 1 if one byte differs.

Real output, recorded once. The second copy has the d of "demo" in out/report.md changed to D. docs/determinism.md lists what the 11 golden cases do not cover.

Try the recorded run with Python 3.12

The repository holds a recorded run and 11 golden cases. After git clone, these commands need no Docker, GPU, model key or network:

git clone https://github.com/virqdroid/swarmlabre
cd swarmlabre

# rebuilds every report file offline; exit 0 only if every byte is the recorded one
python3 -m swarmlabre replay demo/sfaef16e6

# the web UI playing that recording
python3 -m swarmlabre serve --replay demo/sfaef16e6 --speed 8

# the whole suite, golden cases included
python3 -m unittest discover -s tests

# replay every golden case twice and compare with the committed outputs
python3 tests/goldenrun.py --check --twice

You need Docker only to analyse a new file: the agents and Ghidra/jadx run in containers. The tools image compiles Ghidra's decompiler for arm64, so analysis runs on arm64 Linux only today.

What this is not

  • Not a sandbox for running malware: the sample is only read, never executed. Do not point it at a file you could not safely open in a disassembler.
  • Not a claim that a verdict is right. A verdict, a family name and a confidence are a model's opinion, capped by what the board could check. A finding marked byte-checked means the bytes are there at that offset; it does not mean the agent's reading of them is correct.
  • Not repeatable for a live model run. Replay of a recording is byte-identical; a second live run on the same file can differ.
  • Not tested on other CPU architectures, and no check in this repository involves real malware: the tests and the demo use generated benign files only. The tools image builds for arm64 only today.
  • Not tamper-proof. Nothing signs manifest.json; someone who edits a file and recomputes the hashes gets a replay that agrees.

Alpha 0.1.0, a one-person project. It was built and checked on one machine (Linux arm64, Python 3.12.3). Read SECURITY.md before using real malware.
